# FerryDock verification map

This is an incremental map of the current Linux application. It covers the container list/detail dock, Images, Volumes and Networks workspaces, and Compose project configuration/Start/Stop/Restart/Rebuild & restart/Stop & cleanup workspace. A dedicated daemon-wide cleanup page remains planned.

Default development command: `python3 scripts/verify-headless.py`. It renders the real view through WGPU without a desktop window, drives GPUI input events, and checks commands at a fixture Docker boundary. It needs a usable Linux graphics driver and cached dependencies, but no Docker daemon. The flow retains screenshots and structured evidence under `.verification/headless/`; see the skill's Doctor and the [development guide](../../../../docs/development.md#verification).

Native feature runs use the real release binary, an accessible X11 display, and a newly owned Docker fixture/project. The separate log-performance helper prefers native Wayland in a Wayland session, with a demonstrated KDE/KWin adapter and an explicit X11 comparison option. Native screenshots/OCR and read-only daemon observations provide a separate desktop/transport proof.

Headless coverage includes the UI paths listed below, with fixture events at the worker boundary. It does not prove actual Docker operations, real shell execution, clipboard/compositor behavior, or golden-image equivalence.

The source-backed user entry points are listed in each file. The embedded-terminal journey has been exercised, including fixture discovery/search/selection. Logs were observed, but the full native follow-toggle flow stopped at mouse calibration; lifecycle and all/running native mouse steps remain unverified on this display. Inspect has headless GPU proof, but its native helper has not been run. Individual execution results and evidence stay under the ignored `.verification/` directory. When present, `.verification/VERIFICATION.md` contains local run history. This map is not a complete inventory of all behaviors, daemon failures, terminal escape sequences, or supported platforms.

The headless flow also proves Kit Button focus through Tab, Enter/Space activation
without list-shortcut leakage, disabled/loading action protection, both TabBars,
Resizable pointer dragging and minimum height, and visible notification dismissal.
Error notifications remain beyond the normal success timeout. These are virtual
window interactions and fixture-channel requests; no real container action runs.

Each feature file includes the headless command where applicable and its native flow. Keep those proof boundaries distinct. Native `run` owns launch, doctor, selection, drive, evidence and cleanup together. Only claim steps demonstrated by the chosen harness and its observed effects. Add new paths as real features arrive; `/maintain-verification-skill` maintains this map.
